# 0.1.1: Retire Reference Safely

## Context

Completed migration task [0.1](0.1-migrate-reference-service.md) found credential-shaped literals in tracked reference examples/tests and a separate Git history plus client code not included in the server runtime. Its original reference-removal obligation was handed off to this task. Removing a local directory does not revoke externally valid credentials.

## Objective

Retire the read-only reference after recording the owner's preservation decision, preserve useful research inputs, and verify that the maintained repository contains no copied reference credential.

## Scope

Review the [migration inventory](../../docs/migration.md). Record the owner's decision about the reference Git history and ignored local files without copying credential values to tasks or logs. Keep useful, unapproved research under `todo/future/`. Client SDKs will be implemented in independent repositories, one per language; their implementation is not a retirement prerequisite. Remove the reference only after explicit owner approval, then scan references and validate the maintained server.

## Acceptance Criteria

- The owner explicitly approves removal and either verifies preservation or declares the reference history and local-only files unnecessary.
- Unapproved research, designs, and uncertain requirements are retained under `todo/future/`; no approved work requires the checkout.
- No credential-bearing reference file is retained in the maintained repository. The ignored `server/.env` remains as explicitly requested, and `.env.example` contains placeholders only.
- The reference checkout is absent, stale operational references are updated, and local documentation links pass validation.
- The maintained server's full test suite and static analysis pass after retirement.

## Validation

Validated on September 8, 2026:

- The owner declared `arcaptcha-kaftar/` unnecessary, approved its removal, and directed removal of local credentials except the maintained `server/.env`.
- `find . -maxdepth 2 -type d -name arcaptcha-kaftar` returned no checkout.
- A credential-filename scan found only the ignored `server/.env` and safe `server/.env.example`; the example's credential fields are empty.
- A credential-pattern filename-only scan excluding `.git/` and `server/.env` found configuration fields, synthetic tests, and documentation terminology but no copied reference credential.
- Unapproved research was retained at `todo/future/research-and-delivery-plan.md`, updated to rely on maintained migration evidence, and removed from `docs/`.
- `go -C server test ./...`: passed.
- `go -C server vet ./...`: passed.
- Local Markdown link validation: passed.

## Completion Notes

**Completed September 8, 2026.** The owner explicitly waived preservation of the reference history and local-only files. The checkout was already absent when final retirement validation began, so no additional file deletion was necessary. Removing local copies cannot prove that formerly embedded credentials were revoked; external revocation was not independently validated and no credential values were inspected or recorded.

The maintained ignored `server/.env` was preserved as requested. `server/.env.example` remains because it contains empty configuration placeholders rather than credentials. Research and design material that is not approved for implementation now lives under `todo/future/`, and repository rules prevent restoring the retired checkout.
