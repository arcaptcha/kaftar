# 0.1: Migrate Reference Service

## Context

The current repository is the canonical Kaftar project. `arcaptcha-kaftar/` is a temporary, read-only reference implementation with its own Git history, local configuration, generated documentation, build assets, and existing Go service.

The reference must be reviewed and migrated into the planned `server/` application without importing repository metadata, secrets, machine-specific files, or obsolete generated Swagger artifacts. This task preserves observable behavior first; redesign and modernization belong in separate numbered tasks.

## Objective

Create a buildable and testable Go server under `server/` by migrating reviewed source and configuration from `arcaptcha-kaftar/` while preserving the reference service's supported behavior and recording anything intentionally deferred or changed.

## Scope

- Inventory the tracked files, packages, runtime configuration, HTTP API routes, queue contracts, persistence behavior, providers, tests, and deployment assumptions in `arcaptcha-kaftar/`.
- Identify secrets, private dependencies, private infrastructure assumptions, generated files, obsolete files, and machine-specific configuration before copying anything.
- Create `server/` only when migration begins and add a scoped `server/AGENTS.md` only for rules that meaningfully extend the root rules.
- Copy reviewed Go source, tests, module metadata, required runtime assets, and safe example configuration into `server/`.
- Preserve package boundaries and observable behavior unless a change is required to make the migrated server build or test in the new repository.
- Document every required behavior change, compatibility limitation, and deferred redesign as a separate immutable numbered task.
- Keep the reference directory read-only throughout the migration.
- Do not copy `.git/`, `.env`, editor configuration, build output, generated Swagger JSON or HTML, duplicate generated YAML, or unrelated historical artifacts.
- Review vendored dependencies explicitly and copy `vendor/` only when its temporary necessity is documented.
- Add or update repository documentation needed to build, test, configure, and understand the migrated server.
- Hand off reference retirement to [0.1.1](0.1.1-retire-reference-safely.md); retain the reference read-only until its safety and preservation gates pass.

Out of scope:

- Architectural redesign unrelated to completing a safe migration.
- Building the console application.
- Implementing or migrating client SDKs; the owner confirms independent repositories, one per language.
- Credential rotation, history/local-file preservation, and reference deletion, tracked separately in task 0.1.1.
- Selecting the combined-image process supervisor.
- Adding providers, API features, or deployment platforms not present in the reference behavior.

## Acceptance Criteria

- `server/` contains only reviewed project files and has no nested Git repository, committed secret, local environment file, editor configuration, or build output.
- The migrated Go module builds successfully using documented commands from the repository root.
- All migrated server tests pass, and missing coverage for critical reference behavior is added before the reference is removed.
- Supported HTTP routes, queue inputs, message states, retry and scheduling behavior, provider behavior, persistence expectations, and health behavior are inventoried and either preserved or linked to an explicit follow-up task.
- Configuration is represented by safe documentation and an `.env.example` containing no real credentials.
- Private dependencies and infrastructure assumptions are identified; each is removed, replaced, or linked to an approved blocking task.
- Generated Swagger artifacts are not migrated. Any introduced HTTP contract is maintained as human-edited OpenAPI 3.1 YAML at `docs/openapi.yaml`.
- The root `README.md` contains verified server build, test, and startup instructions after the server becomes runnable.
- Relevant documentation indexes and scoped rules are updated.
- The source comparison and reference disposition are documented, and outstanding retirement obligations are explicitly handed off to task 0.1.1 without claiming they are complete.

## Validation

Validated on September 7, 2026 using Go 1.26.5:

- `git -C arcaptcha-kaftar ls-files cmd internal pkg`: all 50 tracked server Go files are represented. A normalized comparison (canonical imports, removed Swagger annotations, gofmt) matches 43 files exactly; the seven intentional differences are four provider implementations, the replaced Bale test, and two sanitized SMS fixture files. See the [file inventory](../../docs/migration.md).
- `git -C arcaptcha-kaftar status --short`: empty; the reference remains unchanged.
- `go -C server mod tidy`: passed after correcting the interrupted module-path migration. Public-only dependency resolution; no reference-relative replacements or vendoring.
- `go -C server test ./...`: passed. The integration test skips unless all explicit isolated-environment variables are supplied.
- `go -C server test -race ./...`: passed for the unit suite. This does not establish race safety of the uninstrumented Docker server under integration traffic.
- `go -C server vet ./...`: passed.
- `go -C server build -o /tmp/kaftar ./cmd`: passed.
- `go -C server mod verify`: all modules verified.
- `gofmt -l` on migrated Go files: clean after formatting.
- `docker build -t kaftar-migration:local server`: passed with the Go 1.26.5 builder. Final source also rebuilt through Compose.
- `docker compose -p kaftar-migration-check config --quiet`: passed using an ignored `server/.env` created from the safe example.
- `docker compose -p kaftar-migration-check -f docker-compose.yml -f /tmp/kaftar-migration-override.yml up --build -d --wait --wait-timeout 120`: passed. A temporary override enabled HTTP only, added a local Nginx sink, and exposed disposable PostgreSQL/RabbitMQ on loopback ports 25432/25672. An earlier Alpine-only sink failed because it lacked `httpd`; no application change was required.
- `curl --fail --silent http://localhost:1404/health`: returned the JSON string `"Ok"`.
- `docker compose -p kaftar-migration-check -f docker-compose.yml up -d --wait --wait-timeout 120`: passed without the test override. Health returned `"Ok"`; a valid outbound HTTP submission returned 503 with the provider disabled, as documented.
- `docker compose -p kaftar-migration-check -f docker-compose.yml -f /tmp/kaftar-migration-override.yml down --volumes --remove-orphans`: passed; disposable validation containers, volumes, and network were removed. The ignored example-based `server/.env` remains for local onboarding.
- `npx --yes @redocly/cli lint docs/openapi.yaml --extends minimal`: valid, one intentional warning about the documented localhost server URL.
- Local Markdown file-link check: passed. Secret/private-import/generated-Swagger scans find no copied reference credentials or private imports; `.env` is ignored and `.env.example` remains trackable.

The integration command, executed from `server/`, was:

```sh
KAFTAR_INTEGRATION_URL=http://127.0.0.1:1404 \
KAFTAR_INTEGRATION_AMQP='amqp://<fixture-user>:<redacted>@127.0.0.1:25672/' \
KAFTAR_INTEGRATION_POSTGRES='host=127.0.0.1 port=25432 user=<fixture-user> password=<redacted> dbname=kaftar sslmode=disable' \
KAFTAR_INTEGRATION_SINK=http://sink \
go test ./internal/service -run TestIsolatedDeliveryIntegration -count=1 -v
```

All five cases passed: immediate delivery, scheduled delivery, terminal failure without retries, one retry then terminal failure, and direct AMQP submission persisted in PostgreSQL and delivered. These credentials belong only to the disposable fixture. No real provider delivery, production database migration, crash/failure-injection recovery, credential rotation, or external history-backup verification was performed.
